01 · Project Overview

System Overview & Architecture

This document defines the complete scope of work, hardware supply, software development, installation, commissioning, and recurring service obligations for the deployment of a remote hydrological surveillance camera system across 74 stations.

Each station is located in a remote geographic environment with no reliable fixed power grid and limited network access. The system is designed around a solar-powered edge computing architecture: a PTZ camera captures time-lapse and programmable directional images, which are processed, buffered, and transmitted by a local edge node over a cellular network to a centrally managed image server maintained by Evon Electric Private Limited.

Scope Boundary — Integration with DHM The Central Camera Management System developed and operated by Evon Electric will expose a documented API for downstream integration. 02 · System Architecture

Architecture & Data Flow

The diagram below illustrates the full data and power flow for a single station, and its connection to the central infrastructure. All 74 stations share the same topology.

Architecture Narrative

At each remote station: The PTZ camera is powered from a 36V DC supply derived from the 12V battery bank via a dedicated DC-DC boost converter. An industrial-grade edge node (mini PC) communicates with the camera over Ethernet using the ONVIF protocol — controlling PTZ positioning, triggering image captures on programmed schedules, storing images locally, and uploading them to the central server via 4G/3G cellular.

An embedded gateway sits alongside the edge node. It reads the battery voltage and solar charge state from the MPPT controller via RS-485/Modbus and provides this telemetry to the edge node. The gateway also acts as a hardware watchdog, capable of recovering the edge node from an unresponsive state — critical for unattended remote installations.

The 4G router provides internet connectivity with dual-SIM failover. The edge node software manages transfer priority: it uses the primary SIM by default, switches to the secondary SIM if the connection drops, and queues unsent images locally (up to one month) until connectivity resumes.

At the central server (hosted and maintained by Evon Electric): all station images are received, indexed, and made accessible through a web-based management platform. Station health, battery status, and solar voltage are visible on a live dashboard. The server exposes a REST API that DHM can integrate with under a separate engagement.

⚡ Critical: Battery Bank Sizing Requirement

3-day backup energy required: 48.5W × 72 hours = 3,492 Wh

Usable energy from a single 12V 100Ah LiFePO₄ (80% DOD): 960 Wh

Batteries required to meet 3-day mandate: 3,492 ÷ 960 ≈ 3.6 → Minimum 4 units in parallel

The requirement specification cites 12V 100Ah as a baseline. With smart power scheduling on the edge node (reduced camera activity at night, optimized capture intervals), 4× 100Ah provides approximately 3.2 days of backup. For full 3-day compliance with margin, we recommend 4× 12V 100Ah LiFePO₄ paired with edge-node-managed power scheduling.

MPPT Charge Controller

The MPPT controller to be supplied will be rated for 40A. While the requirement specifies 20A, a 40A controller is recommended because:

  • The 400Ah battery bank requires higher charge current for timely recovery after 3-day cloud periods.
  • A 40A controller supports up to 480W solar input at 12V — accommodating potential future panel additions.
  • RS-485/Modbus communication port is required for battery and solar voltage telemetry to the embedded gateway.

If a solar array greater than 240W is installed per site, a 20A controller would result in charge current limiting and prolonged recovery times.

Why the Edge Node is Necessary — Technical Justification

The supplied PTZ camera is a network video surveillance device capable of receiving ONVIF commands and transmitting video streams. However, the full set of operational requirements for this deployment — time-lapse scheduling, multi-server parallel upload, offline buffering, connectivity failover, and power telemetry — are not native camera functions. The edge node is therefore an essential system component, not an optional addition.

Requirement Camera Native? Who Handles It
Programmed time-lapse at different PTZ presets No Edge Node software + camera ONVIF API
Dual-server parallel image transfer (FTP/SFTP/FTPS) No Edge Node manages two upload channels
1-month offline storage with resume-on-reconnect No Edge Node (256GB SSD) manages queue
Dual-SIM 3G/4G connectivity with failover priority No Edge Node + 4G Router, software-managed
Online reconfiguration without fixed IP Partial Edge Node VPN/DDNS tunnel for reliable remote access
Solar voltage & battery voltage monitoring No Embedded Gateway → Edge Node → Server
Power supply to camera (36V from 12V battery) N/A DC-DC converter — dedicated hardware
360° panoramic image capture (preset-based stitching) Partial Edge Node orchestrates preset sequence, server stitches
05b · Embedded Gateway Scope

Embedded Gateway — Scope & Firmware

The embedded gateway is a dedicated microcontroller-based hardware module that operates independently of the edge node. It provides two critical functions: power telemetry and system resilience.

Gateway Responsibilities

  1. Communicate with the MPPT charge controller via RS-485 (Modbus RTU) to read solar input voltage, battery voltage, charge current, and state-of-charge.
  2. Relay power telemetry to the edge node via USB serial at configurable polling intervals (default: every 5 minutes).
  3. Generate local hardware alerts (low-battery threshold) for on-site indication.
  4. Act as hardware watchdog for the edge node — if the edge node becomes unresponsive for a configurable period, the gateway cycles its power supply, forcing a clean restart.
  5. Log power telemetry to onboard flash (minimum 7 days of history) as a fallback if the edge node is offline.
Resilience Design Note At remote, unattended stations, software crashes or OS-level hangs on the edge node would otherwise require physical intervention. The hardware watchdog function of the embedded gateway ensures the system self-recovers automatically, materially reducing the need for on-site maintenance visits.

07 · Software & Firmware Development

Software Development — One-Time Scope

All software components listed below are developed as part of this engagement. The development cost is a one-time charge and covers the full deployment of 74 stations plus the central management platform. Bug fixes and corrective maintenance arising from defects in delivered software are included at no additional cost for the duration of the 3-year service term.

A. Edge Node Application (Per-Station Software)

Deployed on the industrial mini PC at each station. Manages all on-site operations.

  1. Camera scheduling engine: Programmable time-lapse schedules per PTZ preset — configurable intervals per direction (e.g., river view every 10 min, panoramic every 30 min, staff gauge hourly). Persistent schedule survives reboots.
  2. ONVIF camera interface: PTZ control, image capture, live stream retrieval via ONVIF Profile S/G/T and camera HTTP API.
  3. Offline storage manager: Indexed local image storage on SSD with automatic expiry. Queues failed uploads for retry; manages a rolling 30-day local archive.
  4. Multi-server upload client: Simultaneous FTP/SFTP/FTPS upload to two configured servers. Per-file checksum verification, retry logic, and upload status reporting.
  5. Connectivity manager: Monitors network state; implements prioritized failover (Wi-Fi → SIM1 3G/4G → SIM2 GPRS) as configurable policy. Logs connectivity events.
  6. Telemetry relay: Reads power data from embedded gateway and forwards to central server on a regular interval.
  7. Remote configuration interface: Secure remote access (VPN tunnel or DDNS-based) allowing camera preset reprogramming, schedule updates, and system parameter changes without physical access or fixed IP.
  8. Health monitoring & heartbeat: Periodic heartbeat to central server; local self-diagnostics (disk space, camera reachability, network state).

B. Embedded Gateway Firmware

  1. Modbus RTU communication with MPPT controller (RS-485); reads voltage, current, SoC, temperature.
  2. USB serial protocol to edge node for telemetry reporting.
  3. Configurable low-battery threshold triggers and alert output.
  4. Hardware watchdog logic: configurable timeout, controlled edge node power cycle.
  5. Onboard data logging (7-day ring buffer in flash).
  6. Field-updatable firmware via edge node USB interface.

C. Central Camera Management Platform

A web-based platform accessible to authorised users. Hosted on the Evon Electric managed server.

  1. Image reception & ingestion: Receives images from all stations via FTP/SFTP; auto-indexes by station ID, direction, capture time, and metadata.
  2. Database & storage management: Structured storage with search by station, direction, date/time range, and image type. Tiered archiving for long-term retention.
  3. Web viewer & image comparison: Browsable image gallery per station; side-by-side temporal comparison of images from the same direction; zoom tools.
  4. Map display: All 74 stations displayed on an interactive map with status indicators (online/offline, last image time).
  5. Power monitoring dashboard: Live and historical battery voltage, solar voltage, and state-of-charge per station. Alert panel for stations below threshold or offline.
  6. Alerts & notifications: Email notifications for low battery, communication failure, and configurable image-gap alerts.
  7. User management: Role-based access control (admin, operator, viewer).
  8. REST API: Documented API for image retrieval, station status, and telemetry — available for future DHM integration.
  9. Remote camera configuration portal: Web UI to update PTZ presets, capture schedules, and upload settings on any station remotely.
Station Limit The platform is designed and infrastructure-sized for up to 100 concurrent active stations. The term "unlimited stations" is a functional description implying no software-imposed cap; it does not imply infinite infrastructure scaling. Key Observations

Resolution Gap — Critical The most significant specification mismatch is camera resolution. The requirement calls for ≥24MP for panoramic images; the Dahua PTZ83440 is a 4MP camera. In practice, for river gauge monitoring and hydrological surveillance, 4MP at 40× optical zoom provides excellent detail at distance. The DORI detect distance is 3,034m. However, the procuring authority should be made aware of this discrepancy if the Dahua camera is being formally proposed. One mitigation is to generate composite panoramic images by stitching 6–12 sequential PTZ positions — the edge node software supports this.
Power Architecture Note This camera is not designed for direct 12V battery integration. The 36V DC requirement introduces a DC power conversion layer that is not a standard assumption in solar-powered field instrument deployments. Our embedded power management scope addresses this, but it represents real added complexity and cost versus a camera designed for 12V or PoE operation.
What the Camera Does Very Well The PTZ83440 significantly exceeds requirements on optical zoom (40× vs 12× required), IR range (350m vs 120m), tilt range, temperature tolerance, and ingress protection. The ONVIF Profile S/G/T compliance makes it well-suited to edge-node control. The RS-485 port, while not used for its intended PTZ control in this integration (ONVIF is used instead), is available as a secondary control channel.
